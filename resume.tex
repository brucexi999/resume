\begin{projectgroup}
\projectheading{Post-Training for a Triton Kernel Agent}{\atrlprojectdates}
ATRL (ICLR 2027 submission) trains an agent to turn PyTorch operators into optimized Triton kernels on Ascend NPUs. The team built a custom Triton kernel agent harness and introduced compaction-aware RL. Compared with untuned Qwen3.6-35B, ATRL raised KernelBench L1 Pass@1 from \textbf{20\% to 73\%} and Fast@1 (correct kernels at least as fast as eager PyTorch) from \textbf{8\% to 23\%}. Recipe: \href{https://github.com/verl-project/verl-ascend-recipe/pull/49}{verl-ascend-recipe PR \#49}.
\begin{resumeitems}
  \item Implemented partial rollout in verl/vLLM to reduce waiting on long-running agent trajectories, accelerating RL training by \textbf{25\%}; added cross-batch scheduling, resumable execution, and importance-sampling correction across policy updates.
  \item Distilled and curated execution-verified SFT trajectories; filtered examples by correctness and speedup, pruned unproductive turns, and compressed reasoning to fit the training token budget.
  \item Manually inspected agent trajectories turn by turn to debug the training system, identifying four issues across prompts, skills, and tool interfaces and proposing fixes.
  \item Integrated a profiler and Ascend-specific optimization skills into the Triton kernel agent's harness for RL training; one agent-generated matmul implementation achieved \textbf{24\% lower latency} (2,886 to 2,197~$\mu$s).
  \item Diagnosed convolution verification failures caused by HF32 reference execution instead of full FP32, correcting an evaluation issue initially attributed to the agent's kernel-generation ability.
  \item Ran controlled ablations of agent harnesses and Ascend-specific skills to inform the RL training setup.
\end{resumeitems}
